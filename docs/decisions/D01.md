## Context and alternatives

The checkout contains planning documents and skills, with no application manifests or source files. The fixed stack remains React, TypeScript, Vite, Tailwind CSS, Node.js and Express. These are tooling choices only. Catalogue schemas, scoring, coverage, endpoints, provider/model choices, storage/auth, deployment transport, service timeouts and supported browsers/languages remain their original decision gates.

## Dependency management

Root package.json: private, type: module, workspaces: ["frontend", "backend"]; root orchestration and dev tools. Both workspace manifests are private/type: module; frontend owns React runtime dependencies and backend owns Express. shared/ stays a source directory, not a third package. No publish scripts.

Create exactly one root package-lock.json using npm 11.6.0; no workspace locks or pnpm/yarn locks. From the root, first use npm install --save-exact to create the lock from already pinned manifests. Subsequent clean installs use npm ci. Dependency additions use npm install --save-exact --workspace frontend <name>@<version>, the backend equivalent, or npm install --save-dev --save-exact <name>@<version> for root tools. These are addition templates, not selected packages. Count manifest and lock changes against the active task's budget. Never use force/legacy-peer-deps to conceal incompatible pins.

No install command is executed in D01. In Windows PowerShell, npm.cmd and npx.cmd are equivalent executable entry points if script policy blocks npm.ps1/npx.ps1; do not alter machine execution policy.

## Source, compilation and test boundaries

Preserve all SPEC §12.1 paths, formats and names. Use UTF-8 Markdown/JSON, UI .tsx, helpers/contracts/backend .ts, stylesheet .css. No empty feature directories or placeholder products are required.

- frontend/tsconfig.json: strict, target ES2022, lib ES2022/DOM/DOM.Iterable, jsx react-jsx, module ESNext, moduleResolution Bundler, noEmit, types ["vite/client"]; include src and ../shared; exclude colocated tests from this application-only check. Vite transpiles/bundles; tsc is the separate typecheck.
- backend/tsconfig.json: strict, target ES2022, lib ES2022, types ["node"], module/moduleResolution NodeNext, rootDir "..", outDir "dist", noEmitOnError; include src and ../shared; exclude test files and dist. Do not set noEmit here: the backend build must emit JavaScript.
- Shared TypeScript is checked in both consumer programs. Backend output preserves the repository-relative layout: backend/src/server.ts becomes backend/dist/backend/src/server.js; shared/*.ts becomes backend/dist/shared/*.js. Do not assume backend/dist/server.js. Use relative .js specifiers in backend/shared TypeScript imports so emitted Node ESM resolves them; import type for type-only contracts. No runtime path aliases or additional shared build step.
- shared/ must remain browser-safe: no backend imports, Node built-ins, process/environment access, credentials or provider SDKs. Frontend may import shared/ but never backend/. Server data access stays backend-owned; catalogue schemas/asset loading remain D02/M05 work. Deployment must package the resulting backend/shared output and any task-required catalogue assets; D07/Z01 determine the adapter.
- tsconfig.tests.json at root: strict, noEmit, target ES2022, module ESNext/moduleResolution Bundler, jsx react-jsx, DOM plus ES2022 libs, Node types; include tests/**/*.ts, colocated .test.ts/.test.tsx files and the TypeScript Vite/Vitest/Playwright config files. Imported implementation files are checked as test dependencies; application-only checks above still enforce their own boundaries.
- frontend/vite.config.ts: React and Tailwind Vite plugins; do not add a separate PostCSS stack or Tailwind config unless a later task needs one. The Tailwind stylesheet import belongs to the existing styles.css work.
- vitest.config.ts: React transform, node environment by default; include frontend/src/**/*.test.{ts,tsx}, backend/src/**/*.test.ts, shared/**/*.test.ts and tests/integration/**/*.test.ts. Browser .spec.ts files are exclusively Playwright. Component tests opt into jsdom using the documented @vitest-environment jsdom file directive; use React Testing Library and explicit cleanup in each component suite, with user-event for interactions. No global test API requirement.
- eslint.config.mjs: flat config with @eslint/js and typescript-eslint recommended rules covering .ts/.tsx and root .mjs config; global ignores for .agents/, .codex/, node_modules/, dist/build outputs, coverage/, playwright-report/ and test-results/. Use import restrictions to reject frontend→backend and shared→backend/Node imports; do not lint installed skill repositories as application code. No typed-lint project service or additional formatter is needed for the baseline.
- Tests: colocated unit/components as SPEC specifies; API/provider/storage tests in tests/integration/; browser journeys in tests/e2e/; static fictional fixtures in tests/fixtures/. Mocked provider success is test evidence, never a substituted live product result. Never retain microphone audio or private records in fixtures.
