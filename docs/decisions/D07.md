## Evidence-based consequences and limits

- Vercel's current WebSocket-specific documentation says WebSockets are available on all plans and documents Node.js server frameworks including Express. The connection is pinned to one Function instance; it closes when the Function reaches its maximum duration. On Hobby with Fluid Compute, Node.js Functions have a 300-second maximum duration. A reconnect must reload state from an external store; instance memory is not durable across reconnects or deployments. The disposable deployed endpoint did not pass its initial HTTP request or WebSocket handshake (403 at the Vercel edge), so this documented support has not been observed from this project.
- WebSockets require Fluid Compute and follow Function limits/pricing, including connection duration and data transfer. The Vercel Hobby plan is limited to personal, non-commercial use. Its listed monthly allowances include 4 CPU-hours, 360 GB-hours of provisioned memory, 1 million Function invocations, 100 GB Fast Data Transfer, and 10 GB Fast Origin Transfer. Exceeding free allowances can pause use until the applicable allowance period resets. Whether this project qualifies for Hobby is unconfirmed.
- Neon documents standard Postgres connection strings usable from Node.js apps and a serverless JavaScript/TypeScript driver over HTTPS/WebSockets. Its Free plan quota and scale-to-zero behavior make it suitable for a bounded prototype, not a continuous-availability or backup guarantee. The signed-in console confirmed this project is Free. A committed dummy row survived a local Express process restart; hosted Vercel DB connectivity and Neon compute restart still need acceptance.
- An older general Vercel Limits page still says Functions do not support WebSocket servers. That page predates the current WebSocket-specific documentation and the 2026-10-20 general-availability announcement. The newer specialized documentation and later changelog are the current evidence used here; this source conflict is retained for future audits.
